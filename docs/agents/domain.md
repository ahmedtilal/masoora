# Domain docs

Masoora uses a single-context layout with a root `GLOSSARY.md` and architecture decision records in `docs/adr/`.

- Read `GLOSSARY.md` and the ADRs relevant to your task before exploring or proposing changes.
- If the glossary or relevant ADRs are absent, proceed. Add domain documentation through `/domain-modeling` when terminology or decisions are settled.
- Use glossary terms in tickets, tests, and proposals. Bring missing terminology to `/domain-modeling`.
- If a proposal conflicts with an ADR, name the ADR and explain why the decision should be reopened.
